# Бот КБЖУ (локальный запуск)

Бот работает на Mac без установленного приложения Telegram: общение с ним идёт с телефона. Фото обрабатывается в памяти, на диск бот его не сохраняет. После распознавания бот отправляет КБЖУ и полный JSON документом в тот же чат. История хранится в Telegram; JSON-файл можно вручную сохранить на телефон. Отдельной базы данных пока нет.

## Провайдеры

Бот поддерживаетE дваE API для распознавания еды:

| Провайдер | API | Флоу |
|-----------|-----|------|
| **LogMeal** (по умолчанию) | `api.logmeal.com/v2` | Фото → сегментация → подтверждение блюда → подтверждение порции → КБЖУ |
| **Spoonacular** | `api.spoonacular.com` | Фото → распознавание → выбор блюда из top-N → КБЖУ |

Переключение провайдера:
- Команда: `/provider spoonacular` или `/provider logmeal`
- Inline-кнопка: после каждого результата КБЖУ отображается кнопка переключения
- Текущий провайдер сохраняется в `bot_token.json` (поле `default_provider`) и переживает перезапуск бота

## Подготовка

1. Создайте бота через [@BotFather](https://t.me/BotFather) (`/newbot`). Полученный токен не отправляйте в чат с помощником.
2. Токен Telegram-бота берётся из `bot_token.json` в этой папке. При необходимости получите его в **@BotFather → /mybots → выберите своего бота → API Token**: формат `числа:длинная_строка`. Не добавляйте `bot` или `Bearer` перед значением. Токен **LogMeal APIUser** берётся из отдельного `token.json` в этой же папке. Не заменяйте один токен другим.
3. Получите свой числовой Telegram ID: например, напишите [@userinfobot](https://t.me/userinfobot). Добавьте в `bot_token.json` поле `"allowed_user_ids": [123456789]`. Не ставьте кавычки вокруг числа. Если хотите узнать ID через нашего бота, оставьте поле отсутствующим, запустите бота, отправьте ему `/start`, затем впишите присланный ID в конфигурацию и перезапустите программу. Пока ID не разрешён, запросы к LogMeal не выполняются.

Пример содержимого `bot_token.json` (укажите действующий токен и свой ID):

```json
{
  "token": "ТОКЕН_ОТ_BOTFATHER",
  "allowed_user_ids": [123456789],
  "spoonacular_api_key": "",
  "default_provider": "logmeal"
}
```

- `spoonacular_api_key` — API-ключ Spoonacular. Получите на [spoonacular.com](https://spoonacular.com/food-api/pricing) (бесплатный тариф: 150 запросов/день). Без ключа команда `/provider spoonacular` будет недоступна.
- `default_provider` — провайдер при запуске бота: `"logmeal"` или `"spoonacular"`.

## Установка и запуск (macOS, Терминал)

```zsh
cd "/Users/r.golov/ai_folder/kbgu/kbju_api"
open -e bot_token.json
```

В открывшемся файле проверьте токен, добавьте свой Telegram ID и сохраните файл. После этого в Терминале:

```zsh
chmod 600 bot_token.json token.json
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python telegram_bot.py
```

После строки «Бот запущен» откройте бота на телефоне и отправьте ему `/start`, затем фото еды (обычным фото либо JPG/PNG-файлом). Программа должна оставаться запущенной на Mac. Остановка — `Ctrl+C`. При следующем запуске установка уже не нужна:

```zsh
"/Users/r.golov/ai_folder/kbgu/kbju_api/.venv/bin/python" "/Users/r.golov/ai_folder/kbgu/kbju_api/telegram_bot.py"
```

Бот сначала отправляет в LogMeal **полученный от Telegram файл без изменений** и пишет в чат «Отправил оригинал». Если LogMeal вернёт именно HTTP 413 (лимит изображения < 1 МБ), бот пишет «Сжатие», уменьшает фото, удаляет EXIF из сжатой копии и повторяет запрос; после успешной повторной отправки пишет «Отправлено сжатое фото». На остальные ошибки повторной отправки нет. Если фото отправлено в Telegram обычным способом, Telegram может изменить его ещё до загрузки ботом; чтобы передать исходный файл камеры, отправьте его как документ (JPG/PNG).

Расчёт использует наиболее вероятные блюда и стандартные порции, а не измеренный вес. Если LogMeal разделил изображение на несколько областей, сообщение показывает расчётный вес и калории по каждой области, помечает общий итог как предварительный; полная разбивка есть в JSON (`nutritional_info_per_item`). Например, шесть ошибочно обнаруженных областей могут дать сильно завышенную сумму. Бот пока не подтверждает блюдо или фактический вес.

В Терминале отображаются события получения фото, размер исходного и (при необходимости) сжатого файла, HTTP 413, `imageId`, число областей, расчётные калории и отправка ответа. Токены и полное фото в журнал не записываются.

Ни бот, ни скрипт локальной проверки не должны запускаться одновременно с другой копией **этого же Telegram-бота** через long polling: Telegram разрешает один активный обработчик `getUpdates` на токен. При переносе на VPS сначала остановите локальный процесс.
